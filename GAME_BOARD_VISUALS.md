# Game Board Visual Environment

The active Game View environment is:

`frontend/public/assets/game-board/castle-office-v001.png`

It is a 1440 × 720 RGB PNG generated as a project-bound environment asset. It contains no roster characters, portraits, dialogue, labels, controls, or logos. All eight characters remain independent runtime objects linked to the existing character profiles.

## Board character presentation

For animated character conversions and new board characters, use
[BOARD_CHARACTER_WORKFLOW.md](BOARD_CHARACTER_WORKFLOW.md). Commander
`snes-rpg/v002` is the approved quality reference; its versioned animated sprite
sheet overrides the static board still while preserving the other roster mappings.

Guardian now uses `cube-wanderer/snes-rpg/v001` through its own board sprite
configuration at the same reduced scale as Commander. Its special animation raises
a hand and reveals a cyan holographic cube. The original Guardian board still is
retained as a fallback; Office `cube-wind/v002` and the canonical Guardian slot remain
unchanged. See that version's README for the reveal timeline and validation.

Healer uses `healer/snes-rpg/v001` at the same reduced board footprint. Her special
action lifts the crosier, brightens its gem and releases a small cyan healing pulse
with her victory-sign gesture. Office `crosier-victory/v002` remains unchanged, and
her original board still is preserved as fallback.

Game View uses a separate late-16-bit JRPG sprite presentation under:

`frontend/public/assets/game-board/characters/v001/`

The mapping in `frontend/src/app/features/game/engine/board-character-assets.ts` connects those board sprites to the same canonical roster IDs used by Jira, settings, focus controls, and the Office View. The Office View keeps its existing animations, posters, portraits, and registry mappings. New custom characters without a board sprite fall back to their configured profile miniature.

`frontend/public/assets/game-board/characters/manifest.json` records the board asset and the Office/source artwork linked to each character. Board revisions must use a new version directory rather than overwriting an approved set.

## Visual contents

- Three arched skyline windows and blue/gold heraldic banners
- Lit fireplace and castle library storage
- Cyan crystal fountain
- Developer workstations with magical blue monitors
- Map/planning board, plants, lamps, armor statues, rugs, and south gate
- Central planning table with a holographic globe

Phaser adds lightweight animated emphasis to the hologram, crystal, fireplace, lamps, and named interaction points. Those effects stop when effects are disabled and remain static when reduced motion is requested.

## Generation prompt

The built-in image-generation workflow used the supplied mockup as a style and layout reference only. The production prompt requested a polished top-down pixel-art fantasy castle office with dark navy, warm amber, refined gold, and cyan magical technology; generous connected walkways; and the visual contents above. It explicitly excluded people, characters, portraits, speech bubbles, text, letters, logos, interface panels, buttons, and watermarks.

The generated source was resized proportionally to the Phaser board size. Do not edit this file to add characters; environmental revisions should use a new versioned filename.

The board-character set used one identity-preserving style-transfer prompt per roster character. Each prompt requested one transparent full-body overworld sprite with intentional pixel clusters, a limited rich palette, a dark outline, a shared ground baseline, and no text, UI, floor, cast shadow, extra character, or watermark. The character-specific prompt preserved each source illustration's clothing, palette, face, and signature equipment.
